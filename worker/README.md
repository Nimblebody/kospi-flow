# 정시 실행용 Cloudflare Worker

GitHub 예약(cron)이 제때 발사되지 않아 뺐다. 실제로 이 저장소에서 예약은
09:30 UTC 로 걸어 둔 것이 19:53 UTC 에 돌았고(KST 04:53), 정작 필요한 시각에는
돌지 않았다. 대신 이 Worker 가 정시에 `workflow_dispatch` 를 때린다.

- 코드: `scheduler.js` (이 저장소가 원본. 대시보드에서 고쳤으면 여기도 맞춰둘 것)

## 크론

Cloudflare 도 UTC 기준이다.

| 크론 | 대시보드 표시(UTC) | KST | 작업 |
|---|---|---|---|
| `30 7 * * *` | At 07:30 AM | 16:30 | 수급 리포트 |
| `0 9 * * *` | At 09:00 AM | 18:00 | 수급 리포트 재시도 (실패했을 때만) |
| `30 11 * * *` | At 11:30 AM | 20:30 | 수급 확정 갱신 **+ 조선 저녁** |
| `30 16 * * *` | At 04:30 PM | 01:30 | 뉴스 (전날 기사) |
| `0 23 * * *` | At 11:00 PM | 08:00 | 조선 아침 |

**대시보드 시각은 UTC 다.** 'At 11:30 AM' 이 KST 20:30 이다. 헷갈리기 쉽다.

무료 플랜은 **계정당 크론 5개** 가 한도다. 위 5개로 꽉 찼다. 같은 시각 작업은
크론 하나에 묶는다(20:30). 더 늘리려면 기존 것을 빼거나 묶어야 한다.

### 크론 목록과 코드가 어긋났을 때
코드(`CRON_JOBS`)에 없는 크론은 **아무것도 부르지 않고 경고만 남긴다.**
예전에는 수급 리포트로 떨어졌는데, 그 때문에 대시보드에 옛 크론(`0 11`, 20:00)이
남고 새 크론(`30 11`)이 빠져 있어도 '리포트 이미 있음, 건너뜀' 만 찍혀 멀쩡해
보였다. 2026-09-16 부터 09-29 까지 20:30 확정 갱신이 한 번도 안 돈 이유다.
Logs 에 `등록되지 않은 크론입니다` 가 보이면 대시보드와 코드를 맞춘다.

### 확정 갱신
20:30 에 같은 날짜를 다시 만들어 덮어쓴다(이미 있어도). 16:30 값은 장 마감 직후라
뒤에 정정이 붙는다. 실측으로 2026-09-10 기관 수급은 16:32 기록본과 나중 값이
18.9% 달랐다. 실패한 날에는 재시도 역할도 겸한다.

### 재시도가 헛돌지 않는 이유
실행 전에 두 가지를 본다.

1. 결과 파일의 날짜가 오늘(뉴스는 어제)이면 → 건너뜀. 조선은 ship.json 의 슬롯별 날짜를 본다
2. 같은 워크플로가 지금 도는 중이거나 최근 10분 안에 돌았으면 → 건너뜀

## 필요한 값

| 이름 | 종류 | 설명 |
|---|---|---|
| `GITHUB_TOKEN` | Secret | fine-grained PAT. 이 저장소의 Actions 읽기/쓰기만 |
| `TRIGGER_KEY` | Secret | HTTP 로 부를 때 붙이는 열쇠. 안 넣으면 열쇠 없이 열림 |

## 확인

    curl https://<워커주소>/health
    curl "https://<워커주소>/?key=<TRIGGER_KEY>"           # 수급 리포트
    curl "https://<워커주소>/?key=<TRIGGER_KEY>&job=news"  # 뉴스
    curl "https://<워커주소>/?key=<TRIGGER_KEY>&job=ship_evening"  # 조선 저녁
    curl "https://<워커주소>/kis-ping?key=<TRIGGER_KEY>"   # KIS(:9443) 가 닿는지

테스트: `node tests/test_worker.mjs` (가짜 GitHub 로 크론 배정·중복 방지·입력을 본다)

두 번째를 연달아 부르면 `skipped: true` 가 나와야 정상이다.

크론이 실제로 발사되는지는 Cloudflare 대시보드의 Worker → Logs 에서 본다.
`cron 30 7 * * 1-5: {...}` 형태로 찍힌다. 건너뛰었더라도 로그는 남는다.

## 멈춘 걸 알아채는 법

리포트가 나오면 텔레그램 알림이 온다. 평일 18:10 까지 알림이 없으면
어딘가 막힌 것이다. 순서대로 본다.

1. Cloudflare → Worker → Logs 에 크론 로그가 있나 (없으면 크론 문제)
2. 로그의 message 가 무엇인가 (`GitHub 응답 401/403` 이면 토큰 만료)
3. GitHub Actions 탭에 실행이 있나 (있는데 실패면 파이프라인 문제)
